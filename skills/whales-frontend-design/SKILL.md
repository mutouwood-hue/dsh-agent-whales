# 画板设计指南

## 先决定这张设计给谁用

明确用户要在这一屏完成什么、平台和屏幕尺寸、哪项信息最重要、从哪里开始操作。把这些落实为首屏层级、主操作和关键状态。已有需求和验收标准时，按它们安排内容。

按这个顺序取视觉依据：

1. **用户给的参考图或文字要求。** 看清结构、比例、字号层级、留白、颜色、组件状态和要保留的交互，只改用户指出的地方。把参考图所在消息放进 `sourceMessageIds`。拿不到图片时，说明你基于哪些可见信息设计。
2. **当前项目。** 在工作区找最接近的界面、组件、字体、样式变量和间距。优先延续项目语言。必要时用 `whales_design_read` 读取同需求的既有画板或项目组件。
3. **从零设计。** 选一个符合用户和场景的视觉方向，给最关键的信息一个清楚的焦点。用字体、留白、对齐和一套一致的颜色层级撑起版面。颜色、阴影、渐变、动效和装饰应有用途。第一屏要能看出这是用户要的产品。

## 写出完整的使用场景

- 用贴合场景的示例数据和短文案。数据页面写出单位、时段和变化。比如「本月足迹」可以让地图承担定位，榜单只显示对决策有用的信息，切换日期时同步更新指标、图例和所选状态。
- 用可辨识的导航、筛选、按钮和选中态。用真实的 React 状态支持任务中的关键交互。按产品需要补齐空态、较长文字、禁用态和返回路径。
- 组件库是素材。需要自己排版时，可用原生 TSX、内联样式或 `export const css`。项目编译后的样式可用 `styleFiles` 带入。照片或插图适合时，用项目已有且可引用的素材。
- 压缩无用标题、徽章、编号、装饰文案和重复卡片。有多个并列区域时，先检查主、次和辅助信息能否一眼分开。

## 先验看，再请用户确认

- 按目标宽度试一次首屏和关键交互。检查字能否读、控件是否像控件、操作前后内容是否真的变化，以及文字、图表、按钮有没有被裁切。对照参考图和项目页面逐项修正。
- `render.status: "ok"` 只提供运行结果。能查看浏览器或截图时再做视觉核对。只能看到诊断时，说明实际验证了什么，并把可交互画板交给用户看。
- 按批注改稿先读取原画板和评论，用原 `artboardId` 更新。改完才在 `resolvesComments` 提交处理过的 ID。保持需求关联，方便用户复审和交接。

设计流程参考 Anthropic 公开文章 [Improving frontend design through Skills](https://claude.com/resources/articles/improving-frontend-design-through-skills)，结合 DSH 工作区、TSX 沙箱和设计批注流程编写。
