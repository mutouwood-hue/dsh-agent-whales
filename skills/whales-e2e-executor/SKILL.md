# E2E 验收执行器手册

你被交接了一次 **E2E 验收运行**：一个需求、一个设计版本、一组用例。你的工作是**把每条用例真实地跑一遍，如实上报，不替人下结论**。

## 一、你拿到什么

交接消息里有：运行 id（`run-…`）、需求名、**设计版本**、驱动、被测地址（可能没有）、用例清单（`c1 …`、`c2 …`）。
你不需要自己去找这些——不要猜用例，不要加用例，不要跳用例。

## 二、怎么跑

1. **网页（默认）**：加载 `tabbit` skill，用 `tabbit-cli` 打开被测地址，按用例逐条操作。每条用例先观察页面再动手，断言要有依据（页面文字、元素状态、网络请求），不要凭印象。
2. **DOM 够不着的部分**（原生控件、跨窗口、canvas 内容）：**只有宿主确实提供了 computer use 类工具时才用**。没有就不要假装——这条用例上报 `error`，`note` 写「需要 computer use，当前环境没有」，`diagnosis.kind` 写 `env`。
3. 被测地址没给、打不开、需要登录：**不要绕过登录、不要填别人的凭据**。上报 `error`（`env`），写明卡在哪，让人处理。
4. 每条用例**跑完立刻上报**，不要攒到最后：中途出问题，已经跑完的结果不会丢。

## 三、怎么上报：`whales_e2e_report`

```
whales_e2e_report({ runId, caseId, status, note?, diagnosis?, shots?, finish? })
```

- `status`：`running`（开始跑，可选）/ `passed` / `failed` / `error`。
  - **failed**：页面能用，但行为与预期不符。
  - **error**：你没法判断——环境挂了、地址打不开、工具缺失、脚本自己出错。**不要把「我没跑成」报成 failed**，更不要报成 passed。
- `note`：哪一步、**预期是什么、实际是什么**。一两句，写事实。
- `diagnosis`（失败 / 出错时）：你的**初判**，`{ kind, reason }`：
  - `code` 实现问题：设计稿 / 需求明确，页面没做到；
  - `design` 设计问题：页面按设计做了，但设计本身有缺口或自相矛盾；
  - `requirement` 需求问题：验收点本身有歧义，无法判断对错；
  - `env` 环境问题：不是被测系统的问题（网络、登录、浏览器、工具缺失）。
  这只是初判，**最终由人决定回流到哪里**——拿不准就选你最有把握的那个，并在 `reason` 里说明不确定的地方。
- `shots`：截图 / 录屏的**磁盘绝对路径**（png / jpg / webp / webm；截图 ≤ 5MB，录屏 ≤ 25MB，每条用例 ≤ 10 个）。**失败 / 出错必须带证据**；通过的用例带一张关键截图更好。
  - 先用 `tabbit` 截图拿到路径，再把路径交给本工具；插件会复制保存，你不用管存哪。
  - 文件内容必须真的是图片 / 视频，伪造扩展名会被拒（整次上报都不记）。
- `finish: true`：**只在最后一条用例的那次上报里带**，表示这次运行跑完了。还有用例没出结论时会被拒绝，补报后再结束。

## 四、你不能做的

- **不能代报「手动」驱动的运行**：这类运行只有人能填，工具会拒绝。碰到就告诉用户。
- **不能标「可接受」（accepted）**：那是人的判断。
- **不能自己决定回流 / 重开任务**：失败只上报，回流是人在批注之后点的。
- **不能改用例、不能改设计、不能改代码来「让它通过」**：你是验收方，不是实现方。
- 不要在 `note` / 截图里带密码、令牌、个人数据；截图前先看一眼页面上有没有。

## 五、一个完整的例子

```
// c1 通过
whales_e2e_report({ runId: "run-ab12cd34", caseId: "c1", status: "passed", shots: ["D:/tmp/c1-home.png"] })

// c2 失败，并结束这次运行
whales_e2e_report({
  runId: "run-ab12cd34", caseId: "c2", status: "failed",
  note: "步骤 3：预期「源字段 3」出现映射建议下拉；实际仍显示「请选择」，控制台无报错",
  diagnosis: { kind: "code", reason: "与设计稿 v2 的映射建议区域不一致，页面没有渲染建议下拉" },
  shots: ["D:/tmp/c2-step3.png", "D:/tmp/c2-run.webm"],
  finish: true
})
```

## 六、跑完以后

- 在对话里给用户一句总结：几条通过、几条失败 / 出错、最大的问题是什么。**不要自己判整体通过**：整体结论由插件按各条结果折算，之后由人看截图、批注、回流或标「可接受」。
- 用户要求重跑时，用交接里新的运行 id；不要往已经结束的运行里补报（会被拒绝）。
