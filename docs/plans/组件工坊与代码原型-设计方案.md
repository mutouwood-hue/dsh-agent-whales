## 1. 问题

现在的原型帧（波次 6，README「原型帧 + 组件库节点」）只能**拼**：

- 词表写死 22 个抽象组件（`lib/prototype-vocab.js`），`validatePrototypeData` 不认识的一律拒绝（`lib/index.js` 约 8813 行）；
- agent 写的是 Puck JSON（`whales_prototype_draw`，`lib/index.js` 约 5939 行），没有写组件代码的地方；
- 布局只有 `Columns` 两栏和三个插槽容器，没有间距 / 对齐 / 网格，没有页面间跳转，没有状态；
- 组件包（如 CDS）只导出「词表 → CDS」的适配表（`tools/component-packs/cds/adapter.jsx`），CDS 里本身有的
  DataTable / FormField / Overlay 等原始组件 agent 碰不到；CDS 里**没有**的组件（比如「审批时间线」）根本造不出来。

用户要的是类似 **Claude Design**（Claude Artifacts 的设计模板，Claude Code 里是 `/design`）的能力：
AI 用真实设计系统组件写代码 → 画布上实时渲染 → 人通过聊天 / 点选留评论 / 直接改来迭代 → 导出或交给开发。

## 2. 已定决策（用户 2026-11-23 / 24）

1. **方向是「代码即设计」**，不嵌 Penpot / FigCraft（它们是矢量工具，造出来的「组件」只是一张图，不是能交给开发的组件）。
2. **新组件只属于当前项目。** 跨项目复用走「导出 HTML → 在新项目导入」（§12）。
3. **CDS 是业务项目**：新组件要不要进 CDS 由业务自己确认，**插件绝不自动往 CDS 里加任何东西**，也不提供「一键提交到 CDS」。
4. **组件代码用 TSX**：业务项目以 React 为主，Vue 是兜底，**本方案不管 Vue**。
   样式一律写 Tailwind 类名、对到 CDS token；能用原生元素 + 类名解决的不引 CDS 组件，需要真实行为（下拉、表格、上传…）才引。
5. 现有 Puck 原型帧**保留**，作为轻量线框；新能力与它打通（§10），不替换。
6. 用户找人开发，本文是交付物。

## 3. 不做什么（本期）

- 不支持 Vue / 其他框架；不做多人实时协同编辑同一份源码；
- 不自动、也不提供「推到 CDS」；不改 CDS 仓库；
- 不做完整的 Figma 式自由矢量绘图（拖动 / 对齐写回源码放在 P3，只覆盖常见情形）；
- 不引入远程打包服务（Sandpack 默认的 CodeSandbox bundler 不用）；
- 不让 AI 代码在 DSH 主页面的 JS 上下文里执行（§13）。

## 4. 总体结构

```
               ┌──────────── 插件宿主（Node，lib/index.js）────────────┐

               │   · 校验 + sucrase 编译 TSX → JS（编译错误当场返回）    │
               │   · 源码 / 编译产物 / 元数据落盘：design/<projectId>/… │
               │   · 画布元素（kind=component / artboard）只存引用+哈希  │
               │   · 等浏览器回报渲染结果（有画布开着时，§8.3）          │
               │ HTTP：/design/*（人改源码、评论、导出导入，同源 token）  │
               └──────────────────────────▲────────────────────────────┘
                                          │ fetch / POST
 ┌──────────── DSH 页面（React Flow 画布，lib/client.js）────────────────┐
 │  组件节点 / 画板节点 ── 预览 = 沙箱 iframe（§6）                         │

 │  Puck 编辑器：项目组件出现在积木栏，渲染时是一个个沙箱「岛」（§10）       │
 └───────────────────────────────────────────────────────────────────────┘
                     │ postMessage（只传数据：编译后 JS、props、回报）
             ┌───────▼──────── 沙箱 iframe（sandbox="allow-scripts"，不同源）──┐
             │ 自带一份 React / ReactDOM（运行时 chunk 以文本传入）           │
             │ CDS 组件包（bundle.js 文本传入）+ Tailwind 浏览器编译器         │
             │ 执行组件 → 渲染 → 回报：错误、尺寸、DOM 摘要、可选截图、导出 HTML │
             └───────────────────────────────────────────────────────────────┘
```

两类新东西：

| | 组件（component） | 画板（artboard） |
|---|---|---|
| 是什么 | 一个可复用的 React 组件，有 props | 一整页，可以有状态、交互、跳转到别的画板 |
| 归属 | **项目级**（不挂需求，所有需求都能用） | **需求级**（带 `requirementId`，和原型帧一样进需求带） |
| 能被谁用 | 画板、其他组件、Puck 原型帧（作为积木） | 只能被看 / 被链接 |
| 进设计版本 | 被本需求画板 / 原型帧用到的，进快照（§11） | 进快照 |

## 5. 数据模型与存储

### 5.1 落盘位置

沿用插件数据根（`PROPOSAL_STORE_DIR` = `<DSH_HOME>/agent-whales/`，`lib/index.js` 约 2187 行）：

```
<DSH_HOME>/agent-whales/design/<projectId>/
  components/<Name>/
    source.tsx          源码（≤ 64KB）
    compiled.js         宿主编译产物（sucrase 输出，CommonJS 形态，见 §6.2）
    meta.json           { name, title, description, propsSchema, examples, imports, sourceHash, compiledHash, packId, updatedAt, updatedBy }
  artboards/<artboardId>/
    source.tsx / compiled.js / meta.json   （meta 多 width、requirementId、links）
  comments.json         评论钉（§9.3）
  versions/<reqId>/v<N>/…   确认设计时复制的源码快照（§11）
```

- `Name`：PascalCase，`^[A-Z][A-Za-z0-9]{1,39}$`，项目内唯一；不能与当前组件包导出的名字、词表 22 个名字重名。
- `artboardId`：同 `prototypeId` 规则（`FLOW_ID`：1–32 位小写字母数字连字符）。
- 上限（可调，写成常量）：每项目组件 ≤ 100、画板 ≤ 100；单文件源码 ≤ 64KB；编译产物 ≤ 256KB。

### 5.2 画布元素（小，仍走 `applyCanvasElements`）

`CANVAS_ELEMENT_KINDS`（`lib/index.js` 约 8636 行）加 `"component"`、`"artboard"`。元素 `data` 只放引用与展示用字段，**不放源码**
（不动 16KB 上限，也不需要再像原型帧那样放宽）：

```js
// 组件
{ id: "comp:ApprovalTimeline", kind: "component",
  data: { name: "ApprovalTimeline", title: "审批时间线", sourceHash, propsSchema, examplesCount, packId } }
// 画板
{ id: "board:import-flow-1", kind: "artboard",
  data: { artboardId: "import-flow-1", title: "导入 · 上传", width: "desktop", sourceHash, uses: ["ApprovalTimeline"], links: ["import-flow-2"], requirementId } }
```

- 写源码 = 先落盘，再 upsert 元素（`sourceHash` 变了 → `updatedAt` 变 → 需求脏判定自动生效）。
- **锁定沿用现有语义**：人改过（`userEdited`）的元素，agent 再写返回 `locked`（`applyCanvasElements` 约 8702 行）。
  落盘那一步也要先检查锁，**被锁时不能先把文件写了**——顺序是：读元素 → 判锁 → 写文件 → upsert（CAS 冲突重试 3 次，同 `whales_prototype_draw`）。
- 删除元素时连带删目录；被其他组件 / 画板 `import` 的组件，删除前要提示「被 X、Y 用到」（人可以强删，agent 不能）。

### 5.3 propsSchema

**沿用词表的字段口径**（Puck 字段类型），这样项目组件可以直接进 Puck 积木栏：

```json
{ "steps":  { "type": "textarea", "label": "节点（每行一个：名称|状态）" },
  "current":{ "type": "number",   "label": "当前步骤" },
  "tone":   { "type": "select",   "options": ["default", "compact"] },
  "footer": { "type": "slot" } }
```

允许 `text / textarea / number / select / radio / slot`；`defaults` 写在 `examples[0]`。

## 6. 运行时：沙箱 iframe 与编译

### 6.1 为什么必须是不同源的沙箱

现有组件包用 `new Function` 在 **DSH 主页面**里执行（`tools/flow-chunk/proto/entry.jsx` 29–42 行）。那是用户自己放进
`component-packs/` 的可信代码，可以接受；**AI 写的代码不行**：一次提示注入就能让它读到同源的 `x-whales-token`
（`/canvas/elements` 等写路由靠它鉴权，约 8852 行），进而改画布、改需求。所以：

- iframe 用 `srcdoc` + `sandbox="allow-scripts"`，**不给** `allow-same-origin`（不同源，拿不到父页面任何对象和 Cookie）；
- `srcdoc` 里带 CSP：`default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:`
  ——不能发网络请求、不能外传数据。**`'unsafe-eval'` 是必需的**（组件包 bundle 与编译产物都用 `new Function` 执行），
  去掉它沙箱直接抛错；
- 父页面只通过 `postMessage` 和它说话，消息格式固定、带 `runId` + **一次性 nonce**，未知消息丢弃。

**⚠️ P0 实测修正（2026-11-24，Chromium + `srcdoc` + `allow-scripts`）：不要用 `event.source` 做身份校验。**
原写法「父页面校验 `event.source === iframe.contentWindow`」在实际测试里会把沙箱的回消息丢掉，实测现象：

| 观察 | 实测值 |
|---|---|
| 子 → 父消息的 `event.origin` | 恒为 `"null"`（不透明源，符合预期） |
| 子 → 父消息的 `event.source` vs `iframe.contentWindow` | 观测到**不稳定**：简单页面上相等；页面复杂（挂过别的脚本、DOM 变深）后出现过不相等 |
| 沙箱里 `window.parent` | **不是父页面的 window**（`window.parent === window` 或别的代理），所以从子侧也拿不到父页面任何对象 |

**审计意见（P0 审计第 4 条，已采纳）：上面第三行是可靠的，前两行的「不稳定」结论证据不够硬**
（当时的最小复现页本身用 `if (event.source !== frame.contentWindow) return;` 当过滤器，把「不相等」当成了结论输入而不是测出来的）。
所以这一条按**保守口径**采纳：

**结论与实现口径**（P1 起照此写）：

1. 校验组合：**`event.origin === "null"` + 父页面生成的一次性 nonce 原样带回 + 消息类型白名单 + 字段形状校验**。
   即使 `event.source` 可用也不依赖它——这样即使将来浏览器行为变化，协议也不会静默失效。
2. **nonce 必须每次握手一份、且 init 与 render 分开**：同一页面可能同时有多个沙箱 iframe（Puck 的沙箱岛，§10），
   共用一个 nonce 会让多个沙箱互相冒认。父页面每次 `init` / `render` 各生成一个新的随机 nonce（128 bit），
   子页面原样带回，父页面只认「自己刚发出去、还没用过的那个」，用过即废。
3. 安全性不降低：沙箱仍读不到父页面任何对象、Cookie、localStorage，CSP 仍禁全部网络（见 §13 的实测清单）。
4. 若要 `event.source` 可比对，只有两条路，都不该选：给沙箱加 `allow-same-origin`（等于把 token 交给 AI 代码），
   或用 `MessageChannel`（父页面把 port 经 init 传进去，之后只走 port）。port 可以作为后续加固，但不是必需。

后果：**iframe 里要有自己的一份 React**（不同 realm 拿不到宿主共享的 React）。做一个运行时 chunk，
父页面以文本传进 iframe 执行，浏览器内存里缓存一份。

**P0 实测：运行时 140.7 KB 原文 / 45.1 KB gzip**（React 18.3.1 + ReactDOM production + 本文小 runtime，esbuild IIFE + minify）。
构建期必须 `NODE_ENV=production`（见 §6.2 的 jsx-dev-runtime 空桩问题）。

### 6.2 编译放在宿主

- 宿主用 **sucrase**（MIT，纯 JS，体积小、快）把 TSX 编译成 JS：`transforms: ["typescript", "jsx", "imports"]`、
  `jsxRuntime: "automatic"`、**`production: true`**。

  > **⚠️ P0 推翻了原方案的 `production: false`（2026-11-24 实测）。** 原文想用 `production: false` 保留 `jsxDEV` 的 `__source`
  > 行列号给评论钉用，这条路**走不通**，有两个独立的坑：
  >
  > 1. **`react/jsx-dev-runtime` 在 production 下是空桩。** React 18.3.1 的
  >    `react-jsx-dev-runtime.production.min.js` 全文只有
  >    `'use strict';var a=Symbol.for("react.fragment");exports.Fragment=a;exports.jsxDEV=void 0;`
  >    —— `jsxDEV` 是 `undefined`。只有 development 版才是真实现。要用它就得把 development React 塞进沙箱（体积、性能、噪音都更差）。
  > 2. **sucrase 的 `__source` 只有行号、没有列号。** 产物是
  >    `_jsxdevruntime.jsxDEV.call(void 0, 'div', {...}, void 0, false, {fileName, lineNumber: 12}, this)`，
  >    **完全没有 `columnNumber` 字段**（改 `jsxPragma` / `jsxFragmentPragma` 也不出）。同一行多个元素时（`<div><span>a</span><Button/></div>`）
  >    行号无法区分，评论钉会钉错元素。
  >
  > **改用的做法**：编译走 `production: true`（正常 `jsx/jsxs`，无 `__source`），评论钉的「源码行列」改为
  > **编译期静态表**：用 `@babel/parser` 解析源码，收集每个 `JSXOpeningElement` 的 `{line, column}` 与标签名，
  > 再用 `magic-string` 把 `data-wsrc="e<i>"` 插进开标签（P0 已实测：插入不破坏其它字符，插入点全部合法）。
  > 运行时 DOM 上就有 `data-wsrc`，人点中元素 → 查表得行列 → 评论钉 / P3 写回都靠它。
  > 这样**不需要 jsxDEV、不需要 `__source`、不需要 development React**，且行列精度比 `__source` 更高（到列）。
- 为什么不在浏览器里编译：agent 写入时就能拿到编译错误（不依赖有没有人开着画布）；产物落盘，预览时直接用，不用每次编译。
  人在浏览器里改源码时，也 POST 给宿主编译（几十毫秒级）。
- 编译前做**导入白名单**检查（不是靠运行时报错）：只允许
  - `react`；
  - `@cds` —— 当前组件库节点选中的组件包的**原始导出**（§7）；
  - `@project/<Name>` —— 本项目其他组件（检查存在、检查无环）；
  - 其余一律拒绝，报「只能 import react / @cds / @project/*」。
- **沙箱侧的模块映射**（P0 踩坑，实现时照抄）：编译产物与组件包 bundle 都是 CommonJS，沙箱要提供 `require`：
  - `react` / `react-dom` / `react-dom/client` → 运行时里的那一份；
  - **`react/jsx-runtime` 必须暴露原始函数**（`{ jsx, jsxs, Fragment, __esModule: true }`，不能再套一层箭头函数包装）。
    两个原因：① sucrase 生成 `_jsxruntime.jsx.call(void 0, ...)`，取的是裸函数，不能依赖 `this`；
    ② 组件包（esbuild 产物）用的是**命名导入** `import { jsx, jsxs } from 'react/jsx-runtime'`，经过 `__toESM` 包装后，
    箭头函数包装版会取不到（表现为 `jsxDEV is not a function` / `Pl.jsxDEV is not a function` / React error #130，极易误判成组件库问题）；
  - `react/jsx-dev-runtime` 不必提供（`production: true` 用不到）；
  - `@cds` → 组件包 `raw` 摊平的对象，要标 `__esModule: true` 且 `default` 指回自身（sucrase 的 `_interopRequireDefault` 行为）；
  - `@project/X` → 本项目组件的编译产物。
  - **`react` 也要标 `__esModule: true` 且 `default` 指回自身**（P0 审计补充）：`import React from "react"` 经 sucrase 的
    `_interopRequireDefault` 会取 `.default`，CDS 的 CJS `react` 没有 `default` 键，不补这一层就会拿到 `undefined`。
- 组件约定：`export default function Name(props)`；可选 `export const examples = [...]`、`export const tweaks = {...}`（§9.5）。
  画板约定：`export default function Board({ navigate })`，`navigate("<artboardId>")` 跳转到同需求的另一个画板。

### 6.3 样式：Tailwind + CDS token

- **P0 实测结论：CDS 的 `styles.css` 是 Tailwind v4 预编译产物，覆盖常用类但确有缺口，不需要引入 Tailwind 浏览器编译器。**
  在 CDS 3.0.8 的 136.3 KB `styles.css` 上逐类验证（同源 iframe 注入同一份 CSS 后读 `getComputedStyle`）：

  | 类 | 结果 | 类 | 结果 |
  |---|---|---|---|
  | `flex` / `flex-col` / `grid` / `items-center` / `justify-end` | ✅ | `gap-4`(16px) / `gap-8`(32px) / `gap-2` / `gap-3` | ✅ |
  | `p-5`(20px) / `p-4` / `pt-2` / `mt-4` | ✅ | **`gap-7` / `mt-7`** | ❌ 无样式（`normal` / `0px`） |
  | `text-2xl` / `text-sm` / `font-semibold` / `text-muted-foreground` | ✅ | **`col-span-2` / `grid-cols-[1fr_2fr]`** | ❌（`auto` / `none`） |
  | `bg-muted` / `rounded-lg` / `shadow-lg` / `border-t` / `w-full` | ✅ | **`max-w-lg`** | ❌（`none`） |
  | token 变量 `--primary` / `--border` / `--radius` / `--cds-space-*` 等 | ✅ 齐全 | | |

  **口径**：不引 `@tailwindcss/browser`（省掉一次体积与 CSP 风险），改成宿主侧补 CSS。**具体口径（P0 审计要求补齐）**：

  | 问题 | 口径 |
  |---|---|
  | content 扫什么 | **只扫这一次要渲染的组件源码**（`source.tsx` + 它 `@project/*` 依赖的源码 + 组件包里 raw 组件的字面量类名不用扫——那些已在 CDS 的 `styles.css` 里），不扫整个项目 |
  | 「缺哪个类」怎么算 | **不解析 `styles.css` 的选择器**（Tailwind 4 产物里有 `@layer`、变体、任意值，正则判不可靠）。做法：宿主侧用 Tailwind 3 正常生成一遍，再与组件包 `styles.css` 的**类名集合**做差（类名集合靠一个轻量扫描器从 CSS 里取 `.xxx` 选择器得到），只保留差的那些 |
  | 顺序与优先级 | 补充 CSS 作为**后注入的 `<style>`**（在组件包样式之后）；若组件包用 `@layer utilities`，补充样式不再套 layer，直接落在最外层以便覆盖 |
  | 失败兜底 | 补 CSS 生成失败时**不阻塞渲染**，只在工具返回里给 `styleWarnings`（列出可能没样式的类），并照常下发原始 `styles.css` |
  | 「用了 CDS 没有的类」提示 | `whales_design_write` 的返回里对这类类名给 `styleWarnings`（不阻塞，只提示），系统提示与 `pack-api` 同时写「间距/圆角/栅格只用已有 token 类」 |
- 内置 shadcn 包的配色映射现成可抄（`tools/flow-chunk/build-proto.mjs` 19–39 行）。
- 系统提示与 `whales_design_read` 的 `pack-api` 都要告诉 agent：**颜色 / 间距 / 圆角只用 token 类名，不写十六进制色值和魔法数**
  （和 `cds-design` / `frontend-code-style-spec` 的规范一致）。

### 6.4 沙箱协议（父 ↔ iframe）

| 方向 | 消息 | 内容 |
|---|---|---|
| 父 → 子 | `init` | `nonce`、runtime 文本、组件包 `bundle.js` + `styles.css` 文本、补充 CSS、⚠️ 不传截图库（见下） |
| 父 → 子 | `render` | `nonce`、`runId`、入口（组件 + 某个 example / 画板）、依赖的编译产物 `{ name: code }`、props |
| 子 → 父 | `rendered` | `nonce`、`runId`、`ok`、错误（编译 / 运行 / 控制台 error）、内容尺寸、DOM 摘要（节点数、文本长度、空白检测）、`data-wsrc` 命中列表 |
| 子 → 父 | `pick` | 人点中的元素：`data-wsrc`（→ 编译期静态表查到行列）、标签名、文本片段、包围盒（评论钉 / 直接改用） |
| 子 → 父 | `snapshot` | 按需：**静态 HTML**（导出用）。**截图不在沙箱里做**（见下） |
| 子 → 父 | `navigate` | 画板跳转请求（父页面切换预览，不在 iframe 里导航） |

**⚠️ P0 实测：沙箱内截图不可行。** 方案原写「`modern-screenshot` 在沙箱里截，「🔍 验证 CSP 下可用」——实测**不可用**：
异源沙箱（`origin: "null"`）里该库内部会读 `window.document` 做回退，浏览器报
`SecurityError: Blocked a frame with origin "null" from accessing a cross-origin frame`，位图、SVG 两条路径都在同一步抛错。
**改为**：

- 画布上的「预览」是**活着的 iframe**，不需要截图（人直接看）；
- 需要把效果交给 agent「看」时，**截图由父页面做**（父页面能对 iframe 区域截图，P0 已实测通过：
  按 `iframe.getBoundingClientRect()` 裁剪截图即可得到正确渲染的画面）；
- 导出 HTML 时用沙箱回报的**静态 HTML**（`root.innerHTML`）+ 组件包 CSS，不需要截图；
- **agent 拿不到截图像素**：DSH 的工具结果必须是 lossless JSON（`dsh-tools` 的 `snapshotProjection` → `snapshotJsonValue`），
  插件工具**无法**返回 image block。只有内置 `read_image` 工具能返回图片。「让 agent 看见效果」这条路因此**做不到**，
  只能给 **DOM 摘要 + 错误 + 可见文本**，并在工具结果里如实说明「未提供图像」。

运行时错误用 React ErrorBoundary + `window.onerror` + `unhandledrejection` 兜住，渲染出错时画布显示红框和错误，不白屏。

### 6.5 性能（P0 实测，用于给 ✅/❌ 定阈值）

同一页面并行创建 N 个**独立沙箱 iframe**（每个都自装运行时 + 662 KB 组件包 + 渲染一次），实测：

| N | 创建 N 个 iframe | 全部 boot + 渲染完成 | 已用 JS 堆 |
|---|---|---|---|
| 1 | 1 ms | 242 ms | 40 MB |
| 5 | 9 ms | 867 ms | 43 MB |
| 12 | 107 ms | 1025 ms | 69 MB |
| 30 | 77 ms | 1605 ms | 74 MB |

结论：**30 个沙箱岛在同页面并行时，量级在 1～2 秒内全部出图**（当时实测 1.6 s），方案原设的「单个原型帧 ≤ 30 个实例」
阈值**暂定保留**。但要诚实说清两件事：
1. **这组数字没有留存、且测量方法有缺陷**（无基线、无 `gc()`、串行创建时间混进加载时间）——审计已记为「未验证」。
   P1 实测时要按「创建前基线堆 → 逐岛 performance.measure → 结束后 gc 再读堆」重做，并写 `render-log.json`。
2. 这是**并行、同页面**的极端情形；Puck 里每个实例都是独立 iframe 且各自要再装一次组件包，建议实现时对同一组件包做
   「运行时 + bundle 文本」的父页面级缓存（`Map<packId+hash, text>`），避免重复拉取与重复编译。

## 7. 组件包扩展：把 CDS 原始组件和它的 API 交给 agent

现在 `build.mjs` 只打 `adapter.jsx`（词表适配）。要加两样东西（只改插件仓库里的构建脚本，**不碰 CDS 仓库**）：

1. **原始导出**：`adapter.jsx` 里写 `import * as raw from "@company/cds-react"` + 文件末尾 `export { raw }`（与
   `export * as raw from …` 语义等价；按这两行实现，esbuild 打 CJS 目标的产物更可预期，`bundle.js` 里是 `raw:()=>…`）；
   沙箱里 `import { DataTable } from "@cds"` 就解析到 `raw.DataTable`。
   清单 `manifest.json` 加 `"raw": true`。没有 `raw` 的旧包，`@cds` 导入报「当前组件包不支持直接引用组件」。
   **P0 已实现并实测**（`tools/component-packs/cds/adapter.jsx` + `build.mjs`），但代价要说清：
   bundle.js 从 **112.2 KB 涨到 646.7 KB（5.8×）**，因为 `export *` 把 CDS 的全部导出（**448 个，其中 276 个是函数/组件**
   ——含图表、图谱、AI 对话面、富文本等重型子路径）一并带进来。这是**已知且接受的代价**（只在用户机器上本地构建，
   不进插件发布包），但给出两条可选削峰措施，P1 实现时按实测再定：
   - 按 `api.json` 里的组件清单生成**显式命名导出白名单**（只导出文档化组件，预计可砍到 300 KB 上下）；
   - 或按「用到了哪类组件」拆成多个 bundle，预览时按需下发。
2. **API 说明**：构建时从 `@company/cds-react` 的 `.d.ts` 抽出每个导出组件的 props（名称、类型、是否必填、JSDoc 一句话），
   写成 `api.json`。`GET /component-packs/:id/api.json` 只读下发（扩展 `handleComponentPacksRequest`，文件白名单加一项）。

   **P0 已实现并实测**（TypeScript compiler API 读 `dist/index.d.ts`，CDS 3.0.8 的 464 KB 扁平 rollup 声明）：
   抽到 **403 个组件 / 171.5 KB**，其中 33 个 props 解不出（标 `unresolved`）。关键实现要点：
   - 组件 = 末尾 `export {…}` 里**首字母大写的 function / const**。⚠️ 只认 `declare function` 会漏掉 `declare const Upload`
     这种 `forwardRef` 形态（Upload / Checkbox / DatePicker 等 100+ 个全丢）；
   - props = 声明第一个参数的类型 → 同名 interface 字段；`react.ForwardRefExoticComponent<A & B>` 取 `A`；内联对象类型直接读；
   - 泛型组件（`DataTable<T>`）保留 `generic`，字段类型原样（`T` 由 agent 自己替换）；
   - 字段压成 `[名, 类型, 必填, 说明]` 四元组并截断：不压是 200.8 KB（**超 200KB 上限**），压完 171.5 KB；
   - 构建脚本要 `absolute` 化 `--cds` 路径（`createRequire` 不认 `.dev\x` 这种相对目录）。
   - **没有 typescript 依赖时要显式说「跳过」**，不悄悄不产出文件。

   **⚠️ 体积上限修正**：原写「≤ 200KB」是按全量估的，实测 403 个组件压完 171.5 KB 尚可，但 CDS 会继续长。
   建议把上限提到 **1 MB**（它只在用户机器上生成、不进发布包），并把「超出上限」处理成「只留文档化组件」而不是直接放弃。

内置 shadcn 包同样补 `raw`（导出 Button / Card 等）和手写的 `api.json`，保证没有 CDS 的机器也能用。

## 8. Agent 工具与系统提示

### 8.1 只加 2 个工具

工具数被 `test/tools-slim.test.mjs` 钉在 12 个（R 系列精简的结果），这次 **+2 → 14**，同步改测试里的清单与 README / 随包 skill。

**`whales_design_write`** —— 写组件或画板

```jsonc
{
  "kind": "component" | "artboard",
  "name": "ApprovalTimeline",          // kind=component 必填
  "artboardId": "import-flow-1",       // kind=artboard 必填
  "title": "审批时间线",
  "source": "…整份 TSX…",              // 与 edits 二选一
  "edits": [{ "find": "…", "replace": "…", "all": false }],   // 局部修改，省 token；find 必须唯一命中（同 pencil execute 的 edits 口径）
  "propsSchema": { … },                // 组件可选；不给就沿用旧的
  "examples": [ { … } ],               // 组件可选，≤ 8 组
  "width": "desktop" | "mobile",       // 画板可选
  "requirementId": "…",                // 画板可选，规则同 whales_prototype_draw
  "sourceMessageIds": ["m12"]          // 必填，规则同 whales_prototype_draw
}
```

返回：`{ written, kind, id, compile: { ok, errors[] }, render: { status: "ok"|"error"|"unverified", errors[], size, domSummary }, locked?, uses[] }`。
编译失败**不写盘**，直接把错误（行列 + 摘录）返回给 agent 自己修。

**`whales_design_read`** —— 读

```jsonc
{ "what": "list" | "get" | "pack-api" | "comments", "kind": …, "name"/"artboardId": …, "component": "DataTable" }
```

- `list`：本项目组件（名字、标题、propsSchema 摘要、被谁用）、本需求画板；
- `get`：源码 + meta + 最近一次渲染回报；
- `pack-api`：当前组件包 `api.json`，可按组件名过滤（避免一次塞满上下文）；
- `comments`：未处理的评论钉（§9.3），含行列与源码片段。

### 8.2 系统提示

`FLOW_SECTION_TEXT`（约 1474 行）第 5 条后加一条，要点：

- 现成组件拼得出来就用 `whales_prototype_draw`；要**新组件**或**有交互的整页**才用 `whales_design_write`；
- 先 `whales_design_read` 看已有组件和 `pack-api`，**能复用就复用，不重复造**；
- 新组件只属于本项目，**不要说「已加入 CDS」**，也不要建议自动提交到 CDS；
- 样式只用 token 类名；写完看返回的 `render`，有错先修再回复用户。

### 8.3 渲染回报怎么回到工具结果

工具在宿主执行，渲染只能在浏览器里做。做法：

- 宿主维护一个「画布在线」表：画布页打开某项目时，前端用现有连接（或新增 `/design/live` 长轮询）登记；
- `whales_design_write` 写完后，若该项目有在线画布，下发「请渲染 X」，**最多等 8 秒**拿 `rendered` 回报并带进工具结果；
- 没有在线画布或超时，`render.status = "unverified"`，并在 `render.note` 里如实写「未在浏览器里渲染验证」——**不能假装渲染过**。
- **系统提示要配一条硬规则**（原方案漏了）：`render.status === "unverified"` 时，agent **不得**说「已验证效果 / 渲染正常」，
  要照实说「还没在浏览器里验过」。否则 `unverified` 会被 agent 当成「没问题」回报给用户，等于放弃取证纪律。
- 🔍 **已核实（P0）**：DSH 工具结果**不能**带图片块。`dsh-tools` 的成功结果走 `snapshotProjection` → `snapshotJsonValue`，
  要求 projection 是 lossless JSON；image block 的 `attachment` 是 brand 类型，不是普通 JSON。只有内置 `read_image` 工具走另一条路
  （`attachment` 服务 + `imageReadContent`）能返回 `{ type: "image", attachment }`。**插件工具没有这条通道**，
  所以「让 agent 看见渲染效果」**做不到**，实现只能给 DOM 摘要（节点数 / 文本长度 / 可见文本前 N 字）+ 错误。
  实现时要在工具结果里写清 `render.visual: "unavailable"`，不要暗示 agent 看过画面。

## 9. 画布与人工编辑

### 9.1 节点

- **组件节点**：卡头（名称、AI 标记、被引用次数、「编辑」「导出」）；主体 = 沙箱预览，可切换 examples；
- **画板节点**：同原型帧的外观与缩放（参考 `PrototypeFrame`，entry.jsx 144–169 行，换成沙箱 iframe）；画板之间的 `links` 画成虚线；
- 画板进**需求带**（`requirementId`），组件放在项目级的「组件区」（画布左上固定一列，或单独一个分组框，交互稿里定）。
- 新节点渲染代码放进新 chunk `client.design.js`，**有组件 / 画板节点时才加载**（同 `wbChunkLoader` 四态，client.js 约 7552 行），主包门禁不动。

### 9.2 源码编辑浮层

- 全屏浮层：左源码（CodeMirror 6，MIT，TSX 高亮）、右实时预览（沙箱）、下方错误条；「保存」= POST `/design/source`（同源 token）；
- 编辑器 chunk `client.code.js` 首次点「编辑」才加载；
- 人保存 = `by: "user"` → 元素 `userEdited` → 之后 agent 写入被锁（返回 locked，提示「换个名字另起一版」，同原型帧）。
  提供「解锁让 AI 继续改」按钮（人显式操作才解锁）。

### 9.3 点选留评论（对标 Claude Design 的 inline comments）

- **⚠️ 原方案用自定义 `jsxDEV` + `__source` 不可行**（P0 实测，见 §6.2：production 的 `jsx-dev-runtime` 是空桩、
  sucrase 根本不出 `columnNumber`）。**改为编译期静态表**：
  - 宿主编译时用 `@babel/parser` 解析 TSX，收集每个 `JSXOpeningElement` 的 `{ id, line, column, tag }`（`line` 1-based / `column` 0-based）；
  - 用 `magic-string` 把 `data-wsrc="e<i>"` 插到开标签名之后（`<div` → `<div data-wsrc="e3"`），再交给 sucrase 编译；
  - 运行时 DOM 上就有 `data-wsrc`（P0 已验证：51 个元素全部命中，插入不破坏其它字符）；
  - 同步把这份表存进 `meta.json`（`jsxTable`），评论钉、P3 写回都用同一份行列，**不需要运行时 `__source`**。
- 预览上切到「评论」模式，点中元素 → `pick` 消息（带 `data-wsrc`）→ 弹出输入框 → POST `/design/comments`：
  `{ target: "comp:X" | "board:Y", wsrc, line, col, tag, textSnippet, sourceSnippet, body, author, createdAt, status: "open" }`；
- **⚠️ 同行动态元素的注意事项**：落在 `.map()` / 条件表达式里的元素会渲染出多个实例，同一个 `data-wsrc` 会命中多个 DOM 节点。
  点选时要额外带上「第几个命中」（`nth`），并在源码片段里注明「这一处在循环里」，避免 agent 改错地方。
- 评论作为一条消息发给**该需求的 Composer**（组件评论发给最近写它的会话），复用现有串门 / followup 机制，
  消息里带行列与源码片段，agent 用 `whales_design_read(what:"comments")` 也能拉到；
- agent 改完在 `whales_design_write` 里带 `resolvesComments: [id]`（可选字段）把评论标为已处理；人也可以手动关。

### 9.4 直接改（P3）

- 先做两类，覆盖大部分「改个字、换个颜色 / 间距」：
  1. **文本**：点中文本元素直接改字；
  2. **token 类**：属性面板列出该元素 `className` 里的颜色 / 间距 / 圆角 / 字号类，下拉换成 CDS token 里的另一个；
- 写回源码在宿主做：`@babel/parser`（MIT）按 `line:col` 找到 JSX 开标签 → `magic-string`（MIT）最小替换 → 重新编译；
  找不到（动态拼出的 className、文本来自变量）就提示「这里是代码算出来的，请用评论让 AI 改」，不硬改；
- 拖动 / 对齐写回：参考 Onlook（Apache-2.0）的做法，只做 flex / grid 子项的顺序调整与 gap 调整，**不做绝对定位**。

### 9.5 调节滑杆（tweaks）

组件可声明 `export const tweaks = { gap: { type: "number", min: 0, max: 48, step: 4, default: 16 }, accent: { type: "select", options: ["primary", "neutral"] } }`，
预览旁出现控件，值作为 `__tweaks` prop 传入、即时重渲染；人点「固化」才把当前值写回源码默认值（走 §9.4 的写回）。

  </script>

- 依赖闭包：导出 A 时自动带上 A 用到的项目组件；
- **CDS 是受控包（UNLICENSED）**：导出时让人选「含组件包代码（只在公司内部传）」或「不含（只含源码，打开时 CDS 部分显示占位）」，默认**不含**。
  内置 shadcn 包（MIT）总是可以带。

入口：画布工具条「导入设计」→ 选 `.html` → 宿主解析 `#whales-design` 那段 JSON（**只读这段，不执行文件里的任何脚本**）：

## 13. 安全清单

| 风险 | 措施 |
|---|---|
| AI 代码读同源 token / 改数据 | 沙箱 iframe 不同源（无 `allow-same-origin`），Puck 里也走沙箱岛。**P0 实测的隔离强度**：沙箱里 `parent.__whalesToken` 读不到、`parent.document` 读不到、`parent.localStorage` 读不到；父页面也读不到沙箱文档 |
| AI 代码外传数据 | iframe CSP `default-src 'none'`，无网络。**P0 实测**：沙箱内 `fetch("https://example.com")` 被拦 |
| AI 代码绕过「只能 import」的承诺 | 导入白名单是**文本扫描**，源码里写 `new Function("…")` 能编过（沙箱 CSP 为运行必需开了 `unsafe-eval`）。**这不构成越权**（沙箱仍读不到父页面、无网络），但它意味着「只能 import react/@cds/@project」是**约定**而不是强制。要强制就得加静态拦截（P2 可做） |
| 父页面被伪造消息 | ⚠️ **不能靠 `event.source`**（实测不稳定，见 §6.1）。改：`event.origin === "null"` + 一次性 nonce + 消息类型白名单 + 字段形状校验 |
| 导入文件里的恶意脚本 | 导入只解析 JSON 段，不执行；源码重新编译、重新过白名单 |
| 路径穿越 | `Name` / `artboardId` 正则校验后才拼路径；所有路径 `join` 后检查仍在 `design/<projectId>/` 下 |
| 受控 CDS 代码外流 | 导出默认不含组件包；插件仓库与发布包里永远没有 CDS |
| agent 越权 | 解锁、确认设计、强删被引用组件、导入只有人能做（同源 token 路由，agent 无对应工具） |
