## 1. 判据与全局约束（每个任务都要核对）

1. **不覆盖官方 `conversation` key**；只新增 key 或注册 View（§45.4）。
2. **本期禁止 P3**：不替换 `conversation.session` / `conversation.chat.flow`（§45.3）。
3. **不自动发送**：任何画布→对话的写入只 `insertQuote` + `persistDraft`，保留用户已输入内容。
4. **CAS 纪律**：所有写操作带 `expectedRevision`，冲突返回 `40901 rev-conflict`，**worker/agent 重报，不覆盖，不提供强制写**（§53.9.12）。
5. **「已产出」≠「已送达」**：三态分开报，未知不自动重派（§37.7）。
6. **不替用户做决定**：提案、派发、关闭 report 都由人触发；系统只汇总与提醒。
7. **暗色是风格选项，默认浅色**；主题跟随宿主 `--dsw-alias-*` 变量 + MutationObserver，不自建 token 名（T-6 `gTO9l`）。
8. **节点图只承载三类**：上下文（仓库/文件夹）、Agent、Composer；`flow` 节点只在流程图页（v2.1 §57.5，本期不做）。
9. **依赖 `blockedBy` 不上画布**，只在任务板（§51）。
10. **禁止清单 10 条**见主 PRD「给 AI 的读取入口」，生成任何方案前逐条核对。

## 7. W1 返工轮（W2 审核结论落地）

W2 审核给出 3 项返工 + 3 项文档修正。文档修正（D1 健康码词表、D2 worker preset 落点、
D3 连线语义）已改 PRD 与设计稿；下面是代码侧返工的落地记录。

| 项 | 审核结论 | 落地 |
|---|---|---|
| R1【高】 | 画布**没有 agent 面**：agent 既看不到也改不了画布 | 宿主 `GET/PUT /agent-whales/api/canvas`（位置表 `canvas.json`，`expectedRevision` CAS + `40902` 带当前版本）+ 5 个工具（list / inspect / layout / link / unlink，`presentCall` 分 read/edit）+ 客户端位置改从宿主读写（localStorage 降级为拖拽即时反馈与离线兜底） |
| R2【中】 | 无小地图、网格常开且没有开关 | 小地图（右下角**只读镜像**：节点缩略 + 视区框，刻意不接交互）+ 网格开关按钮（默认开） |
| R3【中】 | 「记住上次选择」只有文案，没有持久化 | `wbRoute` 每次 set 写 `dsh-agent-whales.last-view`，加载时 recall；脏 kind / 坏 JSON / 缺 projectId 一律回落 list；**首次无记录仍是列表** |

**没有 `node_add` / `node_delete` 是刻意的**：画布节点是派生的（上下文←任务落点
`worktree`/`execRoot`、Agent←项目成员、Composer←主会话），让 agent 增删节点等于让它伪造

## 8. 第二轮：画布从「拓扑图」变成「开发工具」（A/C 方向）

所以这一轮的目标是：开发者盯着一个节点时，不用切到任务板/待办页签就能看到它在干什么。

### 8.1 节点检视（`wbNodeInspector` + `WbNodeInspector`）

选中画布节点后，下方展开一块检视面板。三类节点各有各的看点：

| 节点 | 显示 |
|---|---|
| `agent` | 在线/空闲 · 它负责的任务（状态 chip / report 四态 / 落点 / 阻塞原因）· 已完工计数 |
| `folder` | 指向这个落点的任务 · 牵扯到哪些人（去重，用会话标题不用 id） |
| `composer` | 几条提案待确认 · 项目简报写没写 |

口径约束（写进代码注释与测试）：
- **纯函数**（`wbNodeInspector`）不碰 DOM、不发请求，全部从已拉到的快照推导，离线测试同口径；
- 状态词**一律复用** `wbTaskRowView` / `wbInboxView` / `wbReportTone` / `tasks.status.*` / `tasks.report.*`，
  不另造一套——同一个「进行中」不能在两处长得不一样；
- **不算事件归属**：宿主 `eventView` 已核实事件台账不带 `sessionId`，所以检视器不猜；
- 组件自己也要防坏数据：曾经 `data.tasks` 不是数组时 `data.tasks.map` 会抛，
  **一个节点检视能把整块画布带崩**。现在坏数据渲染成降级面板（真 React 下验证过）。

画布页为此新增一次 `/inbox?projectId=` 拉取（composer 节点的提案数需要它）。

### 8.2 不再发明知会失败的请求

`/proposals` 这条路**强制要求 `leadSessionId`**（缺参返 `40000`）。但客户端有两处会在拿不到
lead 会话时照样去打它，于是每 5s 轮询一次、每次必然失败——用户在真实 console 里看到的那片红
主要就是这个。

给 `wbCache` 加了空 URL 语义：传 `null` 就返回**常量空快照**，不建 entry、不起轮询、不发请求。
两处调用点改掉。空快照必须是同一个对象——`useSyncExternalStore` 靠 `Object.is` 判等，
每次新建会让 React 无限重渲染（这类 bug 在假垫片下看不出来，真机上表现为「卡在 loading」）。

### 8.3 目标条不再常驻

没有提案就**整个不渲染**。它是有提案才出现的行动条，不是常驻装饰；传统对话里没有提案，
不该在官方输入框上方占位置。提案接口报错时同样不渲染——拿不到数据就不表态。
`goal.guide` 文案键随之删除（只被那句引导用过）。

### 8.4 验证

- `npm test` **297 全绿**（原 273 → 297，新增 24 条）

  `WhaleWorkbench` / 各页面 / 目标条 / 节点检视（含坏数据降级）全部通过——垫片没有掩盖问题
- 补了 `useSyncExternalStore` **契约测试**：发布才通知 listener、快照在两次发布之间必须稳定、

## 9. 观测层：画布上看到「哪个 Agent 用了哪个工具」

用户提出：装了很多 MCP/agent，能不能**拖一个 MCP 到画布、连到某个对话，就让这个对话只能用这些**；
底层用插话发消息让它用。结论分两层，本节做第一层。

### 9.1 先厘清：这不是「授权」

查了 DSH 源码与类型定义（`@deepseek-ai/dsh-tools`、`dsh-agent-tool-presentation`、`dsh-mcp-client`）：

- MCP 工具注册在 **host plane 的 `ctx.tools`**，全局共享；`dsh-agent-tool-presentation` 的文档原话是
  "One row per composition, **not one per session**"——**没有按会话的工具隔离**。
- `restrict({allow, deny})` 是 "Restrict global tools for **the calling agent scope**"，要按 agent
  限制必须持有那个 agent 的 `agent.ctx`；而 `ctx.agents.get(id)` 只返回 bare `Agent`，handle 只给创建者。
- 所以「链接 = 授权」做不到。**插话那条路能跑通，但它是派活不是授权**（工具全局可见，发消息对方真能执行）。

**且有个大坑**：`ToolRestriction.allow` 的语义是 "keep only; **everything else is removed**"——
按 allow 实现会把 bash/文件读写一起删掉，agent 直接残废。所以约束层必须走 guard/deny 思路。

### 9.2 观测层不需要探针（本轮成果）

原计划先做探针验证 `tools.guard` 能否拿到 `exec.agent`。**探针没能测**——运行中的 DSH 宿主半边
停在旧代码（`GET /api/probe` 404 而 `/api/canvas` 200，证明新代码没加载；touch live 监听的
`cordis.patch.yml` 也不会重新 apply 插件）。**要验证必须重启 App。**

但顺着这条线发现：**会话事件里原生就有 `tool/call`**。解了一个真实落盘会话
（`~/.dsh/sessions/**/session.v4.jsonl.zstd`，Node 24 `zlib.zstdDecompress` 可解），事件类型分布：
`user/message` / `assistant/message` / `tool/call` / `tool/result` / `step/start` / `step/end`，
`tool/call` 的 `data.name` 就是工具名。**会话身份就是 session id**，不需要 `exec.agent`。

我们此前的 `foldMessages` 只抽 `type === "text"`，把 `tool/call` 整个丢掉了——所以一直没发现这条现成数据。

### 9.3 实现

- **宿主**：新增纯函数 `sessionToolCalls(events, limit=8, maxScan=200)`。**从尾部往前扫且有扫描上限**——
  `/sessions` 每 5s 被轮询而 `SESSIONS_MAX_ROWS` 是 500，不能对每个会话全量扫。
  `/sessions` 行新增 `recentTools`（有才给，不塞空数组）。
- **客户端**：`wbNodeInspector` 的 agent 分支新增 `toolNames`（去重、最近优先）与 `toolCallCount`（如实报总次数）；
  `WbNodeInspector` 渲染「最近调用」一行 code 块。
- **只有 Agent 节点给**：落点节点的看点是「哪些任务指向这」，Composer 管提案与派发——给它们列工具调用是答非所问。

### 9.4 验证

- `npm test` **306 全绿**（新增 `test/observe-tool-calls.test.mjs` 5 条 + workbench 4 条）
- fixture 用的是**真实落盘会话解出来的事件**（`test/fixtures/real-session-events.json`），
  不是我编的——这条数据形状此前没人验证过，编一个「看起来对」的 fixture 等于自己骗自己
- 真 React 18.3.1 渲染验证通过

### 9.5 约束层（待重启后验证）

`tools.guard` 的探针代码仍在 `lib/index.js` 里（带 `// ── 临时探针` 标记，`GET /api/probe` 可读状态）。
要回答的只有一个问题：真实 DSH 里 `exec.agent` 给不给。给 → 按 agent 硬拦；不给 → 降级成
「按项目成员会话粗粒度约束」或「只观测 + 提醒」。

- `flow` 在 `lib/index.js` 里 0 处（除了 CSS 的 `overflow`）——没有 `flow.*` 工具
- 提案模型是线性的（trigger → steps → dispatch → report），`4414` 行能看出 steps 是固定链，
  **没有 nodes/edges 图结构**
- 画布 store 一个项目只有一页，没有 page 维度

也就是说：**现在加一个流程图页签，它永远是空的。** 而按 v2.1，用户也不能手动往里加节点
（没有 `sourceMessageIds` 就是不允许生成）。一个永远空、又不让用户自己填的页签，
正是 §11 里排在最高优先级的那类问题——「画布上有个入口，用户照做发现无路可走」，

## 14. 探针实测结论：约束层方案成立（2026-11-11）

DSH 重启后跑了一个真实任务，探针记到 **40 条**工具调用。这是本项目拖最久的一个未知数，
现在有确定答案了。

### 14.1 实测数据

| 观测项 | 结果 |
| --- | --- |
| `status` | 落盘文件里是 `undefined`（见 14.3 的探针 bug），但 entries 有值即证明 guard 装上了 |
| `agentType` 分布 | **`object` × 40 / 40** |
| `agentId` 非空 | **40 / 40** |
| `sessionId` 非空 | **40 / 40** |
| 去重后 agentId | **1 个**：`session-e24c2025-d72a-4965-ba21-314d68c2418f` |
| 工具名分布 | `pwsh` ×36、`skill` ×2、`read` ×1、`edit` ×1 |

关键细节：**`agent.id === agent.session.id === "session-<uuid>"`**。Agent 的 id 就是会话 id
加一个 `session-` 前缀。这意味着从 `exec.agent` 拿到会话身份只需要去前缀，不需要额外映射。

顺带白拿的：`agentShape.options` 里有 `provider: "zhuangjiaqi"` 与
`model: "deepseek-v4.1-flash"`——将来要做「按模型限流」这类事，数据也在手上。

### 14.2 另一半：guard 能不能拒绝

在 `@deepseek-ai/dsh-tools` 的类型定义里逐字核实：

```ts
export type ToolGuard = (execution: Readonly<ToolExecution>) => string | undefined;
```

`ToolExecutionInput`（`lib/types/index.d.ts`）字段：`callId` / `rootCallId?` / `name` /
`arguments` / **`agent?: Agent`** / `parent?` / `signal`。`agent` 的注释原文是
"The agent on whose behalf the call runs (set by the agent loop)"——**由 agent loop 设置**，
不是可选装饰。

`guardReason` 的实现（`lib/index.js` 2531）：

```js
guardReason(exec) {
    for (const guard of this.guards.values()) {
        const reason = guard(exec);
        if (reason !== void 0) return reason;
    }
}
```

**返回 `undefined` = 放行；返回字符串 = 拒绝，且该字符串就是拒绝理由；先拒者赢。**

### 14.3 结论与边界

**方案成立，可以按 agent 硬拦。** 约束层的实现形状：

```js
function mcpConstraintGuard(exec) {
  var index = mcpConstraintIndex();           // 带 2s TTL 缓存
  if (index === null) return undefined;       // 一条约束都没有 → 快路径
  var sessionId = sessionIdOfAgent(exec && exec.agent);
  if (sessionId === "") return undefined;    // 身份取不到 → 放行，不猜
  var entry = index[sessionId];
  if (!entry) return undefined;               // 这个会话没被约束 → 放行
  var server = mcpServerOfTool(exec && exec.name);
  if (server === "") return undefined;       // 不是 MCP 工具 → 放行
  if (entry.servers[server]) return undefined;
  return "该会话未连接 MCP 服务「" + server + "」";
}
```

三个边界要说清：

1. **本次只有 1 个 agent 出现过**（40 条全同源）。机制上身份可用且按会话唯一，
   但「两个 agent 同时跑、互不干扰」这条还没实测。要做的是并发跑两个任务再验一次。
2. **`ToolRestriction.allow` 仍然不能用**。它的语义是 keep only / everything else is removed
   （README 原文），按 allow 实现会把 bash / 文件读写一起删掉。必须走 `guard()` + 自己的
   连线表，只拦 MCP 工具，其余一律放行。
3. **探针自身有个小 bug**：`probeFlush()` 每 3 秒写 `{entries}`，会把 `probeSetStatus()`
   写的 `{installedAt, pid, status}` 冲掉。所以落盘文件的 `status` 永远是 undefined。
   `/probe` 路由读内存不受影响，但**删探针前要知道这件事**，别以为 status 缺失就是没装上。

### 14.4 下一步

约束层从「未知」变成「可实现」。实现顺序：连线表（画布 link 的真源）→ 全局 `guard()` →
只拦 MCP 工具 → 默认全放行 + 一键全清 + 插件可关。前置校验（MCP 没连上时连线拒绝）
同步做。

### 15.3 踩到的坑（按踩到的顺序）

1. **`wbCache` 预热必须用相对路径**。`useWb` 收到的 key 就是缓存 key，`wbApi` 才另加
   `/agent-whales/api` 前缀。用全路径预热，数据落进另一个 entry，页面永远空。
2. **fake fetch 的 router 必须用 `endsWith`**。`/projects/p1` 是 `/projects/p1/mcp-links` 的
   前缀，`indexOf`（含按长度降序）都会把约束请求误分到项目响应上。症状：MCP 数据永远是
   项目数据，页面只显示空占位。
3. **注入的 `t` 必须返回非 key 串，且透传插值 vars**。`wbT` 看到原样返回 key 就认为没翻译，
   回落内置中文表，断言永远对不上。
4. **`gridOn` 是从没声明过的潜伏 P0**。R2 网格开关只有用法没有 `useState`，项目一加载就在
   渲染路径抛 `ReferenceError`；因空项目早返回所以从没被任何提交前的测试拦住。
   网格/小地图代码此前从未提交，一直躺在工作区。
5. **fixture 里 sessions 用 `sessionId` 字段**，`indexById` / `wbSessionRows` 认的不是 `id`。
6. **测试数据里的 `sessionId` 必须是裸 id**。写成带 `session-` 前缀的值，和
   `sessionIdOfAgent()` 剥完的对不上，用例全挂。
7. **`readStoreFile` 遇坏 JSON 会把路径永久标记 readonly**（文件改名 `.corrupt-<ts>`）。
   共用路径会毒化后续用例，「存储坏了」测试必须用独立 `mkdtempSync` 路径并在结尾还原。
8. **`seedStore()` 必须自己设 store 路径**。`test/index.js` 把所有用例文件 import 进同一进程，
   `index.test.mjs` 有用例重指 projects store，模块级设一次会被盖掉（只在并发跑时暴露）。
9. **新测试文件必须登记进 `test/index.js`**，`test/meta.test.mjs` 有「测试入口卫生」断言。
10. **改测试/`lib/client.js` 一律用 `.prd-tmp/*.cjs` 脚本**。内联 `node -e` 的转义反复炸文件
    （`\x27` / `\n` 被 shell 吃掉），ESM 里还不能用 `require`。
11. **渲染树里数组没有 `.props`**。自己写的遍历器少了 `Array.isArray` 分支，整棵子树都被跳过
    （症状：一个锚点都收集不到）。harness 的 `walk` 有这一分支，抄它的形状。
12. **定位 MCP 节点必须按服务名，不能拿「第一个」**。节点按服务名排序，第一个往往已经连过，
    于是该发的请求被本地判重挡下，测试还以为实现坏了。
